# TRUSTTRACE Forensic Dataset Ingestion, Provenance & Validation Specification

**Document Version:** 1.0.0  
**Domain:** Digital Forensic Dataset Ingestion, Cryptographic Provenance, Leak-Free Partitioning, and Quality Gate Validation  
**Compliance Standards:** ISO/IEC 24029 (Robustness of Neural Networks), NIST SP 800-86 (Guide to Integrating Forensic Techniques into Incident Response), Federal Rules of Evidence 902(13) & 902(14).

---

## 1. Executive Overview

Machine learning in digital forensics requires unassailable data provenance, leak-free evaluation partitioning, and rigorous validation. TRUSTTRACE enforces strict evidentiary controls over dataset ingestion to prevent synthetic data fabrication, label contamination, and cross-split test leakage.

Under the TRUSTTRACE protocol:
- Datasets are **never fabricated** or populated with random noise.
- Every imported image possesses cryptographic SHA-256 and Difference Hash (dHash) digests.
- Models are trained strictly on legitimate, documented public corpora or controlled, auditable manipulation samples.
- The runtime model status remains **`NOT_AVAILABLE`** until a genuine, validated dataset is ingested and a checkpoint is trained.

## 2. Target Dataset Directory Structure

Training data must be organized into four mutually exclusive class directories under `data/dataset/`:

```
data/
└── dataset/
    ├── REAL/                     # Unmanipulated camera originals
    ├── EDITED/                   # Splicing, copy-move, localized manipulations
    ├── AI-GENERATED/             # Diffusion, GAN, synthetic generative media
    └── SCREENSHOT-MANIPULATED/   # Localized screenshot & UI document alterations
```

> [!IMPORTANT]
> **Prohibited Directory: `data/dataset/UNKNOWN/`**  
> `UNKNOWN` is an inference-time rejection state triggered by high epistemic uncertainty ($H(p) > 0.40$) or out-of-distribution (OOD) energy detection. It is **not** a supervised training class and must never exist as a training directory.

## 3. Supported Classes & Forensic Definitions

| Class Label | Taxonomy Index | Forensic Definition & Target Distribution | Prohibited Attributes |
|---|---|---|---|
| `REAL` | 0 | Authentic, unmanipulated optical photographs preserving natural sensor noise, valid EXIF metadata, and uniform JPEG compression. | No generative inpainting, splicing, or post-capture synthetic text overlays. |
| `EDITED` | 1 | Digital images containing localized spatial modifications: copy-move cloning, image splicing, object removal, or retouching. | No unmodified originals; no pure text screenshots without tampering. |
| `AI-GENERATED` | 2 | Synthetic visual assets generated by diffusion pipelines (Stable Diffusion, Midjourney, DALL-E) or Generative Adversarial Networks (StyleGAN, ProGAN). | No optical camera originals. |
| `SCREENSHOT-MANIPULATED` | 3 | Digital screenshots exhibiting localized interface modifications: modified transaction figures, altered text, spliced UI icons, or tampered timestamps. | **Unmodified authentic screenshots are NOT in this class.** |

## 4. Legitimate Dataset Sources & Class Mapping

TRUSTTRACE maintains an explicit source mapping configuration in `data/source_mapping.json`. Candidate images must originate from documented, verified forensic datasets:

### 4.1. `REAL` Sources
- **Dresden Image Database:** High-resolution uncompressed authentic photos from 73 camera models.
- **RAISE (Raw Image Dataset):** 8,156 uncompressed raw camera images with verified sensor provenance.
- **Authentic Device Captures:** Verified optical device dumps with authenticated camera metadata.

### 4.2. `EDITED` Sources
- **CASIA v1.0 & v2.0:** Benchmark tampering dataset with localized splicing and copy-move alterations.
- **Columbia Image Splicing Detection Dataset:** Photomontage and splicing evaluation corpus.
- **CoMoFoD:** Comprehensive copy-move forgery dataset with diverse post-processing transformations.
- **COVERAGE:** Copy-move database with similar background and foreground objects.

### 4.3. `AI-GENERATED` Sources
- **CIFAKE:** Curated 60,000 synthetic (Stable Diffusion v1.4) and authentic images.
- **GenImage:** Multi-generator benchmark covering Stable Diffusion, Midjourney, GLIDE, VQDM, and Wukong.
- **DiffusionForensics:** Deep-forensic benchmark for diffusion-model synthetic detection.

### 4.4. `SCREENSHOT-MANIPULATED` Sources
- **Controlled TRUSTTRACE Synthetic Tampering:** Documented, reproducible alterations generated via `data/generate_screenshot_manipulations.py`.
- **Documented UI Tampering Corpora:** Academic datasets capturing altered financial transaction screenshots and manipulated mobile receipts.

> [!WARNING]
> **Unmapped Sources Policy:** Any dataset not explicitly listed in `data/source_mapping.json` is classified as `UNMAPPED` and rejected. Filename heuristic guessing is strictly prohibited.

## 5. Controlled Screenshot-Manipulation Data Protocol

Because public datasets for payment proof and UI screenshot tampering are scarce, TRUSTTRACE provides a deterministic generator: `data/generate_screenshot_manipulations.py`.

### 5.1. Permitted Transformations
1. **`numeric_alteration`:** Modifies payment amounts, account balances, or transaction figures while maintaining background palette coherence.
2. **`text_alteration`:** Replaces text fields while introducing subtle baseline displacement or kerning drift characteristic of synthetic overlays.
3. **`timestamp_modification`:** Alters message timestamps or device status-bar clocks.
4. **`ui_element_splicing`:** Copies UI checkmark badges or status emblems from one coordinate and composites them elsewhere.
5. **`ui_region_compositing`:** Inpaints or blanks a bounding box and overlays synthetic confirmation cards.

### 5.2. Provenance Tracking
Every generated sample records a cryptographic audit log in `data/manifests/screenshot_manipulation_provenance.json`:
- `generated_image_id` & `generated_image_sha256`
- `source_image_id` & `source_image_sha256`
- `transformation_type` & `transformation_parameters`
- `provenance_tag: "SYNTHETIC_FORENSIC_TAMPERING_CONTROLLED"`

## 6. Manifest Specification

Dataset metadata is stored in `data/manifests/`:
- `dataset_manifest.csv`: Master register of all approved images.
- `train.csv`, `validation.csv`, `test.csv`: Partitioned split manifests.
- `rejected.csv`: Audit log of all rejected files with specific failure reasons.

### 6.1. Manifest Schema
```csv
image_id,sha256,source_dataset,source_id,original_path,target_class,width,height,format,file_size,split
img_000001,8a1f4b...,CASIA_v2,Tp_D_CNN_M_N_nat00001.tif,/path/to/img,EDITED,384,256,TIFF,295010,train
```

## 7. Data Leakage Prevention & Split Strategy

To prevent data contamination and unrealistically optimistic validation results:
1. **Cryptographic Deduplication:** SHA-256 digests are computed for all files. Identical payloads are rejected at ingestion.
2. **Perceptual Similarity Analysis:** Difference Hash (dHash) detects near-duplicates (Hamming distance $\le 4$).
3. **Source-Aware Group Partitioning:** Images derived from the same source image, camera device, or generation batch share a `source_group` key. Group members are assigned exclusively to a single split.
4. **Deterministic Partitioning:** Stratified 70% Train / 15% Validation / 15% Test split utilizing a fixed random seed (`seed = 42`).
5. **Cross-Split Assertions:** The quality gate guarantees that $\text{Train} \cap \text{Val} \cap \text{Test} = \emptyset$ in both exact SHA-256 digests and source-group IDs.

## 8. Step-by-Step Operator Guide

### Step 1: Ingesting External Data
```bash
# Ingest an authentic camera dataset
python data/ingest_dataset.py \
  --source-dir /path/to/dresden_raw \
  --source-name dresden \
  --dataset-dir data/dataset \
  --manifests-dir data/manifests \
  --copy-files
```

### Step 2: Generating Controlled Screenshot Manipulations
```bash
python data/generate_screenshot_manipulations.py \
  --source-image data/test_payment_proof.jpg \
  --output-dir data/dataset/SCREENSHOT-MANIPULATED \
  --transformation all
```

### Step 3: Validating Dataset Quality Gate
```bash
python data/validate_dataset.py \
  --data-dir data/dataset \
  --manifests-dir data/manifests \
  --min-samples 10
```

### Step 4: Launching Model Training
```bash
python train_pipeline.py \
  --data-dir data/dataset \
  --manifests-dir data/manifests \
  --arch efficientnet_b0 \
  --epochs 15
```

## 9. Licensing & Ethical Considerations

- **Copyright Compliance:** Academic datasets (CASIA, Dresden, RAISE, CIFAKE) must be acquired under their respective institutional licenses.
- **Exclusion from VCS:** Raw dataset binaries must not be committed to Git. The repository `.gitignore` automatically ignores `data/dataset/**` while preserving directory scaffolding.
- **Chain of Custody:** Federal Rules of Evidence require that forensic models document their training lineage, cryptographic checksums, and temperature calibration tables.
